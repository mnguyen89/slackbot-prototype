# Slacky Component Library

A self-contained component library for building pixel-accurate Slack prototypes. No React, no build step — Claude Code handles the wiring. You describe what you want, and it uses Slacky to build it.

Based on Pendar Yousefi's [design-prototype-kit](https://slack-github.com/pyousefi/design-prototype-kit).

## Overview

Slacky gives you the full Slack design system as ready-to-use building blocks — core components, 688 icons, 1,100+ design tokens, dark mode, and interactive behaviors — so prototypes match the real product by default. It's the foundation of the [Local Prototype Kit](https://slack-github.com/muno/local-prototype-kit) and powers all standalone prototypes deployed to GitHub Pages.

**What's in the box:**

- **Components** (`components.css`) — Foundational Slack UI components: buttons, inputs, modals, menus, cards, tabs, tooltips, and more.
- **Icons** (`slacky.js`) — All 688 icons from the official [Slack icon library](https://slack-github.com/slack/icons).
- **Design tokens** (`tokens.css`) — Every Slack design token: colors (semantic + 240 palette stops in hex + 27 brand), spacing, typography, shadows, radius, and font declarations. These are the source of truth for all design values.
- **Themes** (`tokens.css`) — Light (default), dark, and sidebar theme support. Themes override the same token variables scoped by CSS class — add `sk-client-theme--dark` or `sk-client-theme--sidebar` to any container.
- **Fonts** (`fonts/`) — Slack-Lato font files.
- **Avatars** (`avatars/`) — Persona and app avatar images for prototypes.
- **Pattern guide** (`REFERENCE.md`) — Copy-paste HTML examples for every component. Claude reads this automatically when building prototypes.
- **Starter template** (`starter.html`) — Ready-to-use HTML file with everything already linked.

**Live references:**

- **[Component showcase](https://pages.slack-github.com/muno/slacky-component-library/showcase.html)** — Browsable reference of all components with live demos, search, and dark mode toggle.
- **[MessageKit reference](https://pages.slack-github.com/muno/slacky-component-library/messagekit.html)** — Message anatomy, adjacent grouping, all states (hover, highlighted, pinned, ephemeral, deleted), reactions, reply bar, and actions toolbar.

## Sources

Every value in Slacky traces back to the real Slack product. Nothing is approximated from memory or screenshots.

**Design tokens** (`tokens.css`, `dark.css`) — Direct copies of the token files generated by the Slack design system. These are the same files the webapp uses, including all color, spacing, typography, radius, and shadow tokens.

**Component specs** (`components.css`) — Built by cross-referencing three authoritative sources:

- **Webapp source code** — The LESS source files for each Slack Kit component (button, modal, input, menu, etc.) in the webapp repo. This is the ground truth for how components are built.
- **Slack Kit MCP** — The component API tools (`component_search`, `component_lookup`, `component_examples`) for props, accessibility rules, and usage patterns.
- **Design Tokens MCP** — The token lookup tools (`tokens-search`, `tokens-get`) for resolving semantic token names to actual values.

**Icons** (`slacky.js`) — All 688 icons extracted from `@tinyspeck/icons` v1.4.11, the official [Slack icon library](https://slack-github.com/slack/icons). Each icon is the exact SVG path data from the published package.

**Foundation** — Originally based on Pendar Yousefi's [design-prototype-kit](https://slack-github.com/pyousefi/design-prototype-kit), then rebuilt to use the real token system and verified component specs.

## Getting Started

### With the Local Prototype Kit (recommended)

If you're using the [Local Prototype Kit](https://slack-github.com/muno/local-prototype-kit), Slacky is already included. New prototypes created through that kit are automatically set up. Just tell Claude what you want to build.

### Standalone

If you're not using the kit, you can create a standalone prototype by running this in your terminal:

```
./new-prototype.sh my-prototype-name
```

This creates a new folder with Slacky already set up — components, icons, tokens, fonts, and dark mode all ready to go. Open Claude Code in that folder and start describing what you want to build.

### Updating

#### How you'll know there's an update

When you start a Claude Code session from a directory that has Slacky, Claude will tell you if updates are available — similar to how Figma notifies you when a linked library has changes. This works automatically via the SessionStart hook in `settings.local.json`.

#### How to update

**Standalone (without the kit):** Run this from your `shared/slacky/` directory:

```bash
cd <your-prototype>/shared/slacky
./update-slacky.sh
```

This fetches the latest from the [source repo](https://slack-github.com/muno/slacky-component-library) and updates your local copy. Commit the changes in your prototype repo afterward to deploy.

**Local Prototype Kit users:** Run `./update-kit.sh` from the kit root instead — it updates both the kit and Slacky in one step.

### Common base components

Beyond individual UI elements, Slacky includes foundational Slack page structure:

- **Sidebar** — workspace header, filter, page rows, channels, DMs with presence
- **Message** — full message kit with avatar, name, timestamp, body, reactions, reply bar
- **Composer** — formatting toolbar, text input, attachments, emoji, send

These give prototypes the real Slack page structure instead of floating UI in a blank page.

### Channel message chrome shell

A complete IA4 layout template that wraps prototypes in the full Slack UI, mirroring the real client:

- **Top nav** — back/forward, search, help
- **Tab rail** — workspace icon, Home/DMs/Activity/Files/Later/More, compose, avatar
- **Sidebar** — workspace header, filter, page rows, channels, DMs with presence
- **Channel header** — channel name, members, huddle, notifications, search
- **Channel tabs** — Messages, Canvas, Pins, Bookmarks, Files, Workflow
- **Message pane** — date dividers, messages, reply bars
- **Composer** — formatting toolbar, text input, attachments, emoji, send

Thread panel and standalone templates are also available for other contexts.

## Icons

Slacky includes all 688 icons from the official [Slack icon library](https://slack-github.com/slack/icons). Every icon is a 20×20 SVG that automatically matches the text color around it.

Browse the full icon set at [pages.slack-github.com/slack/icons](https://pages.slack-github.com/slack/icons/). Every icon name on that page works in Slacky — just tell Claude which icon you want and it'll use it.

## Design Tokens

All design values come from Slack's semantic token system — colors, spacing, typography, radius, and shadows. Claude uses these automatically when building prototypes, so values match the real product and adapt to dark mode.

| Category | Range |
|----------|-------|
| **Spacing** | 4px – 48px on a 4px grid |
| **Type sizes** | 12px (micro) – 28px (headline) |
| **Type weights** | 400 (regular) – 900 (black) |
| **Colors** | Semantic tokens for content, surfaces, outlines, brand, and 240 palette stops across 20 color families |
| **Radius** | 2px (subtle) – pill (fully rounded) |
| **Shadows** | Subtle lift to high elevation |

## Contributing

Slacky is a shared resource — improvements here benefit every prototype that uses it.

### What to contribute

- **New components** — Slack UI patterns not yet covered (e.g., new sidebar elements, notification styles, specific dialog types)
- **Component improvements** — Better fidelity to the real product, missing states (hover, active, disabled, focus), accessibility fixes
- **Token updates** — New or corrected design tokens from the Slack design system
- **Icons** — The full library is already included. If a new version of the [Slack icon library](https://slack-github.com/slack/icons) ships with additions, the icon set in Slacky should be updated to match
- **Bug fixes** — Anything that doesn't match the real Slack UI
- **Dark mode** — Missing or incorrect dark theme overrides
- **Documentation** — Improved examples in `REFERENCE.md`, better showcase demos

### How to contribute

1. Create a branch for your work
2. Make your changes and commit
3. Open a pull request on GitHub targeting `main`
4. [@muno](https://slack-github.com/muno) is automatically added as a required reviewer — your changes can't be merged until approved

Once approved and merged, the update will be available to everyone through `./update-slacky.sh` (standalone) or the kit's `./update-kit.sh` (Local Prototype Kit users).

### Guidelines

- **Don't break existing prototypes.** Changes to existing components or tokens affect every prototype that uses them. Test against the showcase page.
- **Keep it vanilla.** No build tools, no preprocessors, no framework dependencies. Slacky is plain HTML/CSS/JS so it works everywhere with zero setup.
- **Match the real product.** The goal is pixel-accurate Slack UI. When in doubt, check the webapp source code or the Design Tokens MCP.
- **Document what you add.** If it's not in `REFERENCE.md` with an example, it doesn't exist for other contributors.
